# AGENTS.md — fyreplace-windows

Windows client app for [Fyreplace](https://fyreplace.net) — C# / WinUI 3 on .NET,
solution `Fyreplace.sln` with `Fyreplace` (app), `Fyreplace.Installer` (WiX) and
`Fyreplace.Tests` (MSTest).

- `Fyreplace/Services/ApiClient.g.cs` is generated by NSwag from `Fyreplace/Services/openapi.yaml`
  at build time — never edit it by hand. Run `prepare.bat` once to create the app/package
  manifests from their `*.template.*` files and the placeholder `ApiClient.g.cs`.

## Fyreplace-wide rules

- **Minimal comments** — write self-explanatory code with precise naming. Add a comment only for a non-obvious constraint or an intentional deviation; never narrate what the code already says.
- **Conventional commits** — commit messages follow the [Conventional Commits](https://www.conventionalcommits.org) format: `type(scope): subject` (e.g. `feat(ui): add dark mode`). Keep them short: a concise subject line (≤ 72 characters) and, when needed, a brief body.

## Commands

| Task | Command |
|---|---|
| Build | `dotnet build Fyreplace.sln` |
| Run tests | `dotnet test Fyreplace.Tests` |

## Project conventions

- Versions are computed from git at build time (`Fyreplace/Directory.Build.targets`: latest tag +
  commit count, branch suffix main=3 / hotfix=2 / release=1) — never bump versions by hand.
- API base URLs per environment are defined in `Fyreplace/Directory.Build.props`
  (`FyreplaceApiUrlMain` / `...Dev` / `...Local`); per-user overrides go in
  `Directory.Build.user.props` (not committed).
- Projects use `Nullable=enable`, `EnforceCodeStyleInBuild` and NuGet lock files
  (`RestorePackagesWithLockFile`) — run `dotnet restore` after changing packages.
